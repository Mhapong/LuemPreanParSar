# บันทึกการทำงาน

เอกสารนี้บันทึกว่าทำอะไรไปแล้วบ้าง แต่ละอย่างทำเพื่ออะไร เจอปัญหาอะไร และแก้อย่างไร เขียนให้คนที่ไม่มีพื้นฐานด้านคอมพิวเตอร์อ่านได้ ถ้าเจอคำที่ไม่รู้จัก ดูได้ที่ [อภิธานศัพท์](docs/GLOSSARY.md)

- **แผนงานล่วงหน้า:** [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md)
- **แผนภาพการทำงาน:** [docs/FLOW.md](docs/FLOW.md)

## สรุปสั้นที่สุด

| | |

| **เสร็จแล้ว** | ตารางแป้นพิมพ์ไทย ↔ อังกฤษ (ตรวจแล้วถูกทุกปุ่ม), ดาวน์โหลดข้อความสำหรับฝึก AI ได้ประมาณ 210 MB และทดลองยืนยันแล้วว่าโปรแกรม "ฟังคีย์บอร์ด → ลบ → เปลี่ยนภาษา → พิมพ์ใหม่" ทำได้จริง |
| **ตัดสินใจแล้ว** | ใช้ CNN เป็น AI หลัก, ตรวจ 2 จังหวะ (ระหว่างพิมพ์ และตอนจบคำ) และทำงานบน Wayland |
| **ปัญหาใหญ่ที่สุดที่เจอ** | ระบบบอกภาษาปัจจุบันผิด จึงแก้ให้โปรแกรมจำภาษาเอง (ดูข้อ 10) |
| **ข้อมูลฝึก** | ✅ พร้อมแล้ว 1.49 ล้านตัวอย่าง (ข้อ 14) |
| **งานถัดไป** | AI วิธีที่ 1–2 และโปรแกรมวัดผล (วันที่ 3) |

## วันที่ 1 (1 ต.ค. 2026)

### 1. เตรียมโปรเจกต์

ก่อนเริ่มเขียนโปรแกรม ต้องจัดโต๊ะทำงานให้เป็นระเบียบก่อน

| ทำอะไร | ทำไม |
|---|---|
| ใช้โปรแกรม `uv` จัดการเครื่องมือ | ทำให้ notebook (Linux) กับ PC (Windows) ใช้เครื่องมือรุ่นเดียวกันเป๊ะ จะได้ไม่เจอปัญหา "เครื่องฉันใช้ได้ แต่เครื่องนั้นใช้ไม่ได้" |
| แยกเครื่องมือเป็นกลุ่ม | เครื่องมือฝึก AI ใหญ่หลาย GB ติดตั้งเฉพาะตอนต้องใช้ |
| แยกโฟลเดอร์ตามหน้าที่ | โค้ดหลัก, สคริปต์, โปรแกรมสาธิต และโปรแกรมตรวจ อยู่คนละที่ หาง่าย |
| ไม่เก็บข้อมูลใหญ่ใน git | ไฟล์ข้อมูลและไฟล์ AI ใหญ่มาก และสร้างใหม่จากสคริปต์ได้ |
| ตั้งค่ากันไฟล์เพี้ยนบน Windows | Windows ขึ้นบรรทัดใหม่ต่างจาก Linux อาจทำให้ไฟล์ข้อมูลเสียเมื่อย้ายเครื่อง |

### 2. ตารางแป้นพิมพ์ไทย ↔ อังกฤษ

**ทำไมสำคัญที่สุด:** ทุกส่วนของโปรเจกต์ใช้ตารางนี้ ถ้าผิดแม้แต่ปุ่มเดียว ข้อมูลฝึก AI จะผิด และโปรแกรมจะพิมพ์ตัวผิด

**ตารางนี้คืออะไร:** บอกว่าปุ่มแต่ละปุ่มพิมพ์ตัวอะไรในแต่ละภาษา มี 4 แถว คือ อังกฤษ, อังกฤษ+Shift, ไทย และ ไทย+Shift ครบทั้ง 94 ตัว เช่น

| ปุ่ม | อังกฤษ | อังกฤษ + Shift | ไทย | ไทย + Shift |
|---|---|---|---|---|
| L | `l` | `L` | `ส` | `ศ` |
| F | `f` | `F` | `ด` | `โ` |

**คุณสมบัติสำคัญ:** 1 ปุ่มให้ 1 ตัวอักษรในแต่ละภาษา จึง**แปลงไปแล้วแปลงกลับได้ของเดิมเสมอ** (`สวัสดี` → `l;ylfu` → `สวัสดี`)

**ทำไมยึดไฟล์ของระบบเป็นต้นฉบับ:** Linux มีไฟล์กำหนดแป้นพิมพ์ไทยอยู่แล้ว ซึ่งเป็นตัวที่คีย์บอร์ดของผู้ใช้ใช้งานจริง ถ้าตารางตรงกับไฟล์นี้ก็แปลว่าตรงกับของจริง ตารางจากเว็บหรือจากความจำอาจผิดได้

### 3. โปรแกรมตรวจตารางแป้นพิมพ์

**ตรวจอะไร:** เทียบตารางของเรากับไฟล์ของระบบทีละปุ่ม

**ทำไมไม่ตรวจด้วยตา:** มี 94 ปุ่ม และสระกับวรรณยุกต์หลายตัวหน้าตาคล้ายกันมาก เช่น `ั ํ ี ๊ ้ ็` ตรวจด้วยตาอาจพลาด โปรแกรมตรวจได้แม่นกว่า และตรวจซ้ำได้ทุกครั้งที่แก้

**ผล:** ✅ ถูกต้องทั้ง 94 ปุ่ม

### 4. โปรแกรมตรวจความถูกต้อง (test)

โปรแกรมเล็กๆ ที่คอยตรวจว่าโปรแกรมหลักยังทำงานถูกต้อง รันซ้ำได้ทุกครั้งที่แก้โค้ด

| ตรวจอะไร | ป้องกันปัญหาอะไร |
|---|---|
| ทุกปุ่มมีคู่ และไม่มีตัวซ้ำ | ปุ่มตกหล่น หรือสองปุ่มให้ตัวเดียวกัน |
| `l;ylfu` แปลงเป็น `สวัสดี` ได้ | แปลงกลับทิศ |
| แปลงไปแล้วแปลงกลับได้ของเดิม | ข้อมูลฝึก AI ผิด |
| เว้นวรรค ขึ้นบรรทัดใหม่ และ emoji ไม่ถูกแปลง | ข้อความเสียหาย |
| หมายเลขปุ่มตรงกับที่ Linux ใช้ | โปรแกรมสาธิตกดปุ่มผิด |
| สัญลักษณ์ `/` อยู่คนละปุ่มในแต่ละภาษา | bug ที่เจอจริง (ดูข้อ 5) |

**ผล:** ✅ ผ่านทั้ง 11 ข้อ

### 5. ตารางหมายเลขปุ่ม สำหรับโปรแกรมสาธิต

**ปัญหาที่แก้:** ตอนฟังคีย์บอร์ด ระบบส่งมาเป็น**หมายเลขปุ่ม** (เช่น 38) ไม่ใช่ตัวอักษร จึงต้องแปลงได้ทั้งสองทาง
- หมายเลขปุ่ม → ตัวอักษร: เพื่อรู้ว่าผู้ใช้พิมพ์อะไร แล้วส่งให้ AI ตัดสิน
- ตัวอักษร → หมายเลขปุ่ม: เพื่อให้โปรแกรมพิมพ์ใหม่ได้

**Bug ที่เจอ:** สัญลักษณ์บางตัว เช่น `/ - . ,` มีทั้งในแป้นไทยและอังกฤษ แต่อยู่**คนละปุ่ม** (`/` อยู่ปุ่ม `/` บนแป้นอังกฤษ แต่อยู่ปุ่ม `2` บนแป้นไทย) ถ้าไม่บอกว่าเป็นภาษาไหน โปรแกรมจะกดผิดปุ่ม **แก้โดย**บังคับให้ระบุภาษาทุกครั้ง

### 6. ดาวน์โหลดข้อความสำหรับฝึก AI

**ทำไมต้องใช้:** ต้องมีข้อความภาษาไทยและอังกฤษจริงจำนวนมาก แล้วนำมาแปลงเป็นตัวอย่าง "พิมพ์ผิดแป้น"

| แหล่ง | จำนวน | ทำไมเลือก |
|---|---|---|
| Wikipedia ภาษาไทย | 20,000 บทความ | คำศัพท์หลากหลาย |
| Wisesight (ข้อความโซเชียล) | 26,703 ข้อความ | ภาษาพูดแบบที่คนพิมพ์แชทจริง มีคำย่อและอังกฤษปน |
| Wikipedia ภาษาอังกฤษ | 20,000 บทความ | ฝั่งภาษาอังกฤษ |

| ตัดสินใจอะไร | ทำไม |
|---|---|
| ตรวจรูปแบบข้อมูลบนเว็บก่อนเขียนโปรแกรม | ไม่ต้องเดา ได้ชื่อและรูปแบบที่ถูกต้องตั้งแต่แรก |
| โหลดแค่บางส่วน | Wikipedia ภาษาอังกฤษทั้งหมดใหญ่ประมาณ 20 GB แต่เราใช้ไม่ถึง |
| สุ่มเลือกบทความ | ถ้าเอาแค่ส่วนต้น จะได้บทความกลุ่มเดียวกัน ข้อมูลจะเอนเอียง |
| ติดป้ายว่าแต่ละข้อความมาจากบทความไหน | ใช้แบ่งข้อมูลตามบทความ กันข้อสอบรั่ว |
| ไม่ใช้ประวัติคำสั่งส่วนตัวในเครื่อง | อาจมีรหัสผ่านติดไปด้วย |

**ผล:** ✅ ได้ข้อมูลรวมประมาณ 210 MB

### 7. เตรียมให้ฝึก AI บน PC Windows ได้

**ทำไมต้องใช้ 2 เครื่อง:** notebook ไม่มีการ์ดจอแยก ส่วน PC มีการ์ดจอ RTX 3070 ซึ่งฝึก AI ได้เร็วกว่ามาก แต่ PC ใช้ Windows

| ตัดสินใจอะไร | ทำไม |
|---|---|
| บันทึก AI เป็นไฟล์ ONNX | ไฟล์ชนิดนี้ใช้ได้ทุกระบบ ฝึกบน Windows แล้วนำมาใช้บน Linux ได้ |
| วัดความเร็วบน notebook ไม่ใช่บน PC | notebook คือเครื่องที่ใช้งานจริง ถ้าวัดบน PC ตัวเลขจะดีเกินจริง |
| เขียนโค้ดให้รองรับความต่างของ Windows | Windows เก็บตัวอักษรไทยและเขียนที่อยู่ไฟล์ต่างจาก Linux |

### 8. เปลี่ยนวิธีทำโปรแกรมสาธิตให้ใช้บน Wayland ได้

**ปัญหา:** Linux มีระบบหน้าจอ 2 แบบ แบบเก่า (X11) ให้โปรแกรมแอบดูการพิมพ์ของกันได้ แบบใหม่ (Wayland) ห้ามแอบดูเพื่อความปลอดภัย ผู้ใช้ต้องการใช้ Wayland วิธีที่วางแผนไว้เดิมจึงใช้ไม่ได้

**ทางเลือกที่พิจารณา**

| วิธี | ข้อดี | ข้อเสีย | ตัดสินใจ |
|---|---|---|---|
| ใช้เครื่องมือของ X11 | ง่าย | ใช้บน Wayland ไม่ได้ | ❌ |
| ทำเป็นส่วนเสริมของโปรแกรมช่วยพิมพ์ | ถูกต้องที่สุด | ยากและใช้เวลานาน ไม่ทันส่ง | ทำหลังส่งงาน |
| **ฟังจากคีย์บอร์ดโดยตรง + พิมพ์ผ่านคีย์บอร์ดปลอม** | ใช้ได้ทั้ง X11 และ Wayland | ต้องขออนุญาตพิเศษ และต้องจำภาษาเอง | ✅ เลือก |

**ข้อดีที่สำคัญที่สุด:** มีแผนสำรองในตัว ถ้า Wayland มีปัญหาตอนสาธิต ก็เปลี่ยนไปใช้ X11 ได้ทันทีโดยไม่ต้องแก้โค้ด

### 9. ขออนุญาตฟังคีย์บอร์ด

ระบบไม่ยอมให้โปรแกรมทั่วไปฟังคีย์บอร์ด เพราะอาจเป็นโปรแกรมขโมยรหัสผ่าน จึงต้องขออนุญาตก่อน

| ทำอะไร | ทำไม |
|---|---|
| เพิ่มผู้ใช้เข้ากลุ่มที่ได้รับอนุญาตให้ฟังคีย์บอร์ด | เพื่อฟังว่าผู้ใช้กดอะไร |
| อนุญาตให้กลุ่มนี้สร้างคีย์บอร์ดปลอมได้ | เพื่อลบและพิมพ์ใหม่ |
| ออกจากระบบแล้วเข้าใหม่ | การอนุญาตจะมีผลกับการเข้าระบบครั้งถัดไป |

**ข้อแลกเปลี่ยนที่ต้องเขียนในรายงาน:** ใครที่อยู่ในกลุ่มนี้ฟังการพิมพ์ทั้งหมดในเครื่องได้ โปรแกรมจึง**ต้องไม่บันทึกสิ่งที่พิมพ์ลงไฟล์เด็ดขาด**

### 10. ทดลองล่วงหน้าว่าวิธีนี้ทำได้จริง

**ทำไมต้องทดลองก่อน:** โปรแกรมสาธิตต้องทำได้ 3 อย่าง คือ ฟังว่าผู้ใช้พิมพ์อะไร, ลบแล้วพิมพ์ใหม่ และเปลี่ยนภาษา ทั้งหมดขึ้นกับพฤติกรรมของเครื่องจริง ซึ่งเดาไม่ได้ ถ้ารอถึงวันที่ 6 แล้วเพิ่งพบว่าทำไม่ได้ จะไม่มีเวลาแก้ จึงใช้เวลา 30 นาทีทดลองตั้งแต่วันแรก

**ผลการทดลอง**

| ทดลอง | ผล | หมายความว่า |
|---|---|---|
| พิมพ์ตามปกติ | ✅ โปรแกรมรู้ทุกปุ่ม ทั้งภาษาไทยและอังกฤษ รวมถึงตอนกด Shift | ฟังคีย์บอร์ดได้ และตารางแป้นพิมพ์ตรงกับคีย์บอร์ดจริง |
| ให้โปรแกรมพิมพ์ `hello` แล้วลบ 2 ตัว | ✅ จอขึ้นว่า `hel` | ลบและพิมพ์ใหม่ได้ |
| อ่านภาษาปัจจุบันจากค่าตั้งของระบบ | ❌ พิมพ์เป็นไทยอยู่ แต่ค่าตั้งยังบอกว่าเป็นอังกฤษ | **ค่าตั้งของระบบเชื่อถือไม่ได้** |
| เปลี่ยนภาษาผ่านค่าตั้งของระบบ | ❌ ค่าเปลี่ยน แต่ยังพิมพ์ออกมาเป็นอังกฤษ | เปลี่ยนภาษาแบบนี้ไม่ได้ |
| ให้โปรแกรมกด Super+Space | ✅ เปลี่ยนเป็นไทย แล้วกดอีกครั้งก็กลับเป็นอังกฤษ | เปลี่ยนภาษาด้วยการกดปุ่มลัดได้ |

**ข้อสังเกต:** ช่วงหนึ่งกดปุ่มแล้วดูเหมือนไม่มีอะไรขึ้น แต่ไม่ใช่ bug ปุ่มเหล่านั้นบนแป้นไทยคือสระและวรรณยุกต์ เช่น `ิ ี ่ ้` ซึ่งต้องมีพยัญชนะนำหน้าจึงจะมองเห็น

**นำผลไปใช้อย่างไร**
- โปรแกรมจะเปลี่ยนภาษาด้วยการกด Super+Space
- โปรแกรมจะ**จำเองว่าตอนนี้เป็นภาษาอะไร** โดยนับว่ามีการกด Super+Space ไปกี่ครั้ง
- **ข้อจำกัด:** ถ้าผู้ใช้เปลี่ยนภาษาด้วยการคลิกปุ่มภาษาบนแถบงาน โปรแกรมจะไม่รู้ จึงต้องมีปุ่มลัดให้รีเซ็ตสถานะ

**ยังต้องทำ:** ทดลองซ้ำบน Wayland 1 ครั้ง (ครั้งนี้ทดลองบน X11)

### 12. เลือก AI: CNN หรือ GRU

| คำถาม | คำตอบ |
|---|---|
| CNN ตอบทันขณะพิมพ์ไหม | ทัน ใช้เวลาไม่ถึง 1 มิลลิวินาที ขณะที่คนกดแต่ละปุ่มห่างกันประมาณ 100 มิลลิวินาที |
| GRU ดีกว่าตรงไหน | อ่านทีละตัวเหมือนคนอ่าน ได้คำตอบของทุกความยาวในรอบเดียว |
| ส่วนไหนช้าจริง | ขั้นตอนลบและพิมพ์ใหม่ (ประมาณ 0.1 วินาทีสำหรับคำ 10 ตัว) ไม่ใช่ตัว AI |

**ข้อสรุป**
- **ใช้ CNN เป็นตัวหลัก** เพราะถนัดหารูปแบบสั้นๆ อย่าง `l;y` ที่ไม่มีในภาษาจริง ทำงานเร็ว และแปลงเป็นไฟล์ ONNX ง่าย ส่วน GRU ทำเพิ่มถ้ามีเวลา เพื่อเปรียบเทียบในรายงาน
- **เก็บข้อมูลฝึกเป็นคำเต็ม** แล้วสุ่มตัดให้สั้นยาวต่างกันตอนฝึก ไฟล์จะเล็กลงหลายเท่า

### 13. ตรวจ 2 จังหวะ

**ปัญหา:** ถ้าตรวจเฉพาะระหว่างพิมพ์ ข้อมูลยังน้อยจึงเสี่ยงแก้ผิด ถ้าตรวจเฉพาะตอนจบคำ ผู้ใช้จะเห็นคำผิดทั้งคำและต้องลบเยอะ

| จังหวะ | ต้องมั่นใจแค่ไหน | บทบาท |
|---|---|---|
| A. ระหว่างพิมพ์ | มากๆ เช่น 99% | แก้เร็วเมื่อมั่นใจมาก |
| B. ตอนกด space | น้อยลงได้ เช่น 95% | เก็บกรณีที่ A ไม่กล้าแก้ เพราะเห็นคำเต็มแล้ว |
| ปุ่มแก้เอง | ไม่ต้องถาม AI | ทางสำรอง |

**เจอระหว่างออกแบบ:** ตอนกด space จอได้รับ space ไปแล้ว เพราะโปรแกรมแค่ฟัง ไม่ได้ขวาง ตอนแก้ในจังหวะ B จึงต้องลบเพิ่ม 1 ตัว แล้วพิมพ์ space คืน

### 14. สร้างข้อมูลฝึก AI ✅

**ทำอะไร:** เปลี่ยนข้อความดิบเป็นตัวอย่าง "พิมพ์ถูก" และ "พิมพ์ผิดแป้น" พร้อมเฉลย ตามขั้นตอนในแผนภาพที่ 2 ของ [FLOW.md](docs/FLOW.md) ใช้เวลารันประมาณ 1 นาที

**ผลที่ได้**

| ชุด | จำนวนตัวอย่าง | ขนาดไฟล์ |
|---|---|---|
| แบบฝึกหัด (train) | 1,188,499 | 199 MB |
| ข้อสอบย่อย (val) | 147,919 | 25 MB |
| ข้อสอบจริง (test) | 149,304 | 25 MB |

| ตรวจอะไร | ผล | หมายความว่า |
|---|---|---|
| พิมพ์ถูก : พิมพ์ผิด | 53 : 47 | ใกล้เคียงครึ่งต่อครึ่ง (ฝั่ง "ถูก" มากกว่าเล็กน้อย เพราะตัวอย่างหลอกเป็นแบบ "ถูก" ทั้งหมด) |
| ตั้งใจพิมพ์ไทย : ตั้งใจพิมพ์อังกฤษ | 48.5 : 51.5 | สมดุล |
| ตัวอย่างหลอก | ประมาณ 5% | รหัสผ่าน, คำสั่ง, คำย่อ, เว็บไซต์ และอื่นๆ |
| ความยาวเฉลี่ย | 11 ตัวอักษร | |
| **ข้อความที่พิมพ์ผิดแป้นแล้วบังเอิญตรงกับคำจริง** | **0.28%** | เกือบทั้งหมดเป็นคำ 2 ตัวอักษร เช่น `wa` อาจเป็นคำอังกฤษ หรือเป็น "ไฟ" ที่พิมพ์ผิดแป้นก็ได้ |

**ข้อค้นพบสำคัญสำหรับรายงาน:** ข้อความที่สั้นมาก (2 ตัวอักษร) บางครั้งแยกไม่ออกจริงๆ ว่าพิมพ์ผิดหรือไม่ แม้แต่คนอ่านก็แยกไม่ได้ นี่คือเหตุผลที่ต้องรอให้พิมพ์ไปสักกี่ตัวก่อน (`k_min`) แล้วจึงให้ AI ตัดสิน ส่วนข้อความที่ยาวกว่านั้นแยกได้เกือบทั้งหมด

**ตัวอย่างข้อมูลจริง**

| หน้าจอขึ้นว่า | เครื่องตั้งเป็น | เฉลย | ตั้งใจพิมพ์ |
|---|---|---|---|
| `จำนวน` | ไทย | ถูก | จำนวน |
| `vjkocitgso4krfu8iy[` | อังกฤษ | ผิด | อ่านแระเหนภาพดีครับ |
| `หะฟะรนื` | ไทย | ผิด | station |
| `tbh` | อังกฤษ | ถูก (ตัวอย่างหลอก) | tbh |

**ตัดสินใจระหว่างเขียน**
- **รับเฉพาะช่วงที่พิมพ์ได้ด้วยแป้นเดียวทั้งหมด:** เช่น `ค.ศ.1926` ถูกตัดทิ้ง เพราะแป้นไทยพิมพ์เลขอารบิกไม่ได้ ถ้าเก็บไว้ ตัวอย่าง "พิมพ์ผิด" จะไม่ตรงกับที่คีย์บอร์ดพิมพ์ออกมาจริง
- **ทิ้งตัวอย่าง "พิมพ์ผิด" ที่บนจอไม่มีตัวอักษรเลย:** เช่น "คต" พิมพ์ผิดแป้นจะได้ `89` ถ้าสอนว่า `89` คือ "พิมพ์ผิด" AI จะไปแก้ตัวเลขที่ผู้ใช้พิมพ์จริง
- **แปลงอักขระที่พิมพ์ไม่ได้ให้เป็นแบบที่พิมพ์ได้:** เช่น `–` เป็น `-` และ `“ ”` เป็น `"` ส่วนช่วงที่มี emoji หรือ `é` ถูกตัดทิ้งทั้งช่วง
- **สุ่มเลือกแบบให้ทุกบทความมีโอกาสเท่ากัน** (reservoir sampling) แทนการเอาเฉพาะบทความแรกๆ
- **ปรับโควตาแต่ละแหล่ง:** รอบแรกได้ฝั่งอังกฤษมากเกินไป (56 : 44) เพราะ Wikipedia ไทยก็มีคำอังกฤษปน จึงเพิ่มโควตา Wikipedia ไทย และลดโควตา Wikipedia อังกฤษ
